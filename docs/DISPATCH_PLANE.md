# Dispatch plane decisions

> Role: decision record (why each contract change is shaped the way it is)
> Status: current
> Updated when: a contract change adds or replaces a decision

The system design lives in easy-podcast's
[dispatch-plane document](https://github.com/falahat/easy-podcast/blob/main/docs/DISPATCH_PLANE.md).
This file records the decisions behind this repo's contract changes; each contract change
adds its rows and cites them. A replaced decision is deleted, not struck through.

## Decisions

| ID | Contract | Decision | Why |
|---|---|---|---|
| D1 | 0.2 | An output may name a folder under `outputs/`. The runner uploads the folder's files and returns a `manifest/v0` of them, marked `kind: "manifest"` on the output. | A pose surface-prep step writes two files per video frame, about 900 for one clip. A manifest is the shape folder inputs already take, so the next step takes a folder output by address, with no copy and no new format. |
| D2 | 0.2 | `kind` on an output is optional; absent means one blob. | Action results stored before 0.2 stay valid without a migration. |
| D3 | 0.2 | The runner reads outputs only through the `outputs/` folder it created, opened as an `os.Root`. A named path outside it, a symbolic link, a file with more than one hard link, any other special file, or a replaced `outputs/` folder fails the job as `fatal`. | Outputs are untrusted compute data. Before 0.2 the runner uploaded whatever path the compute named, so a path or link could publish a file outside the workdir, such as the runner's credential, into the CAS. Retrying the same computation breaks the rule again, so the failure is fatal. |
| D4 | 0.3 | A job declares the most GPU memory it will use (`policy.gpu.memory_mb`) and a mode, `shared` (default), `mps` or `exclusive`. A job without the block never receives a GPU, and a runner offers GPUs only when started with `--gpus`. | Pose stages need 0.6 to 7.4 GB each on a 23 GB L4 or an 8 GB card. Placing them by declared memory lets small stages share a GPU and keeps a 7.4 GB stage off a card it cannot fit. Opt-in at both ends leaves the planes that declare nothing unchanged. |
| D5 | 0.3 | The runner sends a fresh reading of its GPUs (index, UUID, total and free memory, compute processes without the MPS server) with each `lease`; a lease carrying one waits at most 5 s. A shared job fits when the declared memory of the plane's RUNNING jobs on that GPU plus its own stays within the total less `gpu_reserve_mb` (default 1024), and its own figure is at most the GPU's free memory. | The rule of the machines' `gpu-slot.sh`. The declared sum covers jobs that have started but not yet allocated; the live free figure covers programs outside the plane. A reading older than a few seconds is not trusted, so the long-poll is shortened. |
| D6 | 0.3 | An `exclusive` job needs a GPU with no RUNNING job of the plane's and no compute process; a GPU holding one takes nothing else. | Timing runs must have the card alone, as `gpu-slot.sh --alone` gives them. |
| D7 | 0.3 | A GPU job runnable for `gpu_starve_after_s` (default 1200) starts first wherever it fits, and until then the GPUs where a runner asking for work in its lane could place it, once they drain, take no other new GPU job. | Without it a stream of small jobs keeps a large or exclusive job waiting forever. Holding back only those GPUs leaves cards it could never use, and jobs without a GPU, running. |
| D8 | 0.4 | A runner credential (one whose authority grants `right("lease")`) reads only the blobs of jobs it holds a live lease on, the invocation, its inputs and each file of a manifest input, and looks up or stores blobs only while it holds one. The PEP keeps the book of leases from the grants it relays, ends a lease at complete, fail or release, and lets one that heartbeats stop renewing expire after its TTL. | Before 0.4 any worker credential could read every blob whose address it knew, another job's video or outputs included, and store at will. A leaked worker key now reaches only the jobs that worker is running. The PEP already sees every grant on the runner surface, so the dispatcher learns nothing about blobs and runners change nothing; minting a token per lease would have changed both. |
| D9 | 0.5 | `hold` takes a machine out of work by the node name its runners give at `hello`: every runner of that node, connected now or later, gets no new lease and waits in the long-poll as if the queue were empty, while its running work finishes; `hold` returns once that work has settled. `unhold` gives the node work again at once. The fleet view marks each held runner and lists the held machines with their reasons. | The owner shares the laptop, Bigboi and the VM with work started by hand. Before a WSL restart or a demo, a machine must stop taking jobs without losing the one it runs. `drain` names one runner and makes it exit, so it has to be restarted and resumed one runner at a time; a hold names the machine, survives its runners restarting, and needs nothing on the machine itself. |
| D10 | 0.6 | A third artifact kind, `local`, `{kind, node, root, path}` with no address, names a file or folder where it lies on one node, at `path` under a root its runner was installed with (`--root NAME=DIR`). As an input, the runner on that node checks the place through an `os.Root` opened on the root and hands the compute that path; nothing is fetched, hashed or copied. As an output, the compute writes where the request's `roots` says that root lies, names `{root, path}`, and the runner reports the place without reading or uploading it. | A pose run's folders hold gigabytes on the machine that made them, and its next stage runs on the same machine; through the CAS the same run first moved 39 MB, in 4.4 s on Bigboi and 117 s to the VM. In place it moves nothing. A root is installed configuration, like the command, so a job can name only places the owner opened to jobs, and the `os.Root` keeps `..`, absolute paths and links from leading out. The PEP's lease book grants reads only for inputs with an address, so D8 is unchanged. |
| D11 | 0.6 | `policy.node` pins a job to the runners whose `hello` names that node. A claim takes a pinned job only for a runner of that node, and D7 holds back GPUs for a starved pinned job only on that node. A runner given a local input of another node releases the job as `wrong_hardware`; a root it was not installed with, or a missing path, fails it as `bad_input`. | A job on local artifacts can run only where they lie. The dispatcher never reads invocations (D8's reason), so the app states the node it read off the artifacts, and the runner checks it again. A job without a node goes to any runner, as before. |
| D12 | 0.6 | When the dispatcher starts, every RUNNING lease gets a full TTL from that moment. | A dispatcher down longer than the lease TTL used to expire every running lease in its first sweep, failing jobs whose runners were still working and about to report in. A runner that never reports still loses its lease one TTL after the start. |
| D13 | 0.7 | An installed command may write `invoke-failure.json`, `{error_class, message}`, in place of `invoke-result.json` and exit zero; the runner ships the command's log and fails the attempt with that class. A non-zero exit stays `fatal`. | A command could say only "success with an exit metric" or "executor crash", both final, so an application had to re-run failures itself, blind to their cause. Pose's queue re-ran every failure twice more, so 43 jobs repeated a deterministic error three times in two days, while a provider outage that needed a dozen tries got four. The command knows which failures are its own; the HTTP compute already says so in its 500 body, so both executors now report the same thing, and the retry policy stays in the dispatcher. |
| D14 | 0.7 | `policy.max_attempts` may be 1 to 20 (was 1 to 10). | A cloud provider that drops tasks for an hour (Cloud Run, 2026-11-22, 11:30 to 12:30) needs about a dozen tries at the `long` backoff; ten capped that below what the job was promised. Every attempt is still counted and the bound still ends a crash loop. |
| D15 | 0.7 | A job whose cancellation was requested never runs again: a `fail` of any class, a `release` or a lost lease ends it `FAILED`. | With `wait_for_executor` the lease is kept while the executor stops, so the job is still RUNNING when its stop is reported. A stopped executor's retriable failure, a release or its runner dying then re-queued work someone had cancelled, once a lane allowed more than one attempt. |
